Common Failure Patterns and How to Fix Them

1. API Rate Limit (HTTP 429)
# Prompt:
/add weather.py
The NOAA API is returning HTTP 429 errors. Add rate limiting to all NOAA calls
using a token bucket pattern: max 5 requests per second. Use the `ratelimit` package.
Add the import to requirements.txt.


2. Stale Contract Data
/add polymarket.py db.py
Add a staleness check to get_contract_price(): if the price was last updated
more than 10 minutes ago (based on a cached timestamp), force a fresh API call.
Otherwise return the cached value. Use a module-level dict as the cache.


3. CLOB Authentication Failures
# Prompt:
/add execution.py
The CLOB client is raising AuthenticationError intermittently. Add logic to
get_clob_client() that catches this error and automatically re-derives API
credentials (client.create_or_derive_api_creds()) up to 3 times before
raising to the caller. Log each retry attempt.


4. SQLite Lock Errors
# Prompt:
/add db.py
SQLite is raising "database is locked" errors when main.py tries to write while
dashboard.py is reading. Fix this by:
1. Adding timeout=30 to all sqlite3.connect() calls
2. Using WAL mode (PRAGMA journal_mode=WAL) on db initialization
3. Wrapping all writes in try/except OperationalError with 3 retries
Do not change the function signatures.


5. Probability Out of [0,1] Range
# Prompt:
/add weather.py edge.py
Add a validation function validate_probability(p, source) that:
1. Returns None and logs a warning if p is None, negative, or > 1.0
2. Clamps p to [0.0001, 0.9999] if it's just barely outside range
3. Call this function on every probability before it enters the ensemble

Then add an assertion in calculate_ev() that raises ValueError if either
p_model or p_market is outside [0,1] so we catch this at calculation time.
